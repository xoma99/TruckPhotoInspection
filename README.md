# Фотоосмотр ТС — отдельное Android-приложение

Первый каркас проекта: Kotlin, Jetpack Compose, Room. Telegram намеренно не подключён. Приложение рассчитано на локальное создание осмотров и сохранение снимков без интернета.

## Открытие
1. Распакуйте архив.
2. Откройте папку `TruckPhotoInspection` в Android Studio (Giraffe/новее).
3. Дождитесь Gradle Sync.
4. Запустите на Android-устройстве (минимум Android 8.0 / API 26).

## Что включено
- отдельный applicationId `com.nowarro.truckinspection`;
- создание осмотра: госномер, марка/модель, сотрудник;
- 13 обязательных заданий на фото, сгруппированных из 23 предоставленных образцов;
- локальная база Room;
- блокировка завершения, пока обязательные ракурсы не сняты;
- пересъёмка снимка;
- отметка завершённого осмотра.

## Проверка качества снимков (версия 0.2)
- После съёмки выполняется локальный анализ изображения на устройстве.
- Проверяются средняя яркость, доля очень тёмных/светлых пикселей и приблизительная резкость по границам (Laplacian variance).
- При замечаниях приложение показывает причину и предлагает переснять снимок.
- Сотрудник может нажать «Принять вручную»; такое подтверждение сохраняется в базе.
- Для завершения осмотра каждый обязательный ракурс должен пройти проверку или быть подтверждён вручную.

Это предварительная эвристика, а не экспертная оценка: пороги нужно откалибровать на реальных снимках грузовиков и условиях съёмки. Проверка качества не определяет, тот ли ракурс снят, и не распознаёт автомобиль.

## Важные ограничения текущего каркаса
- Фотообразцы лежат в `app/src/main/assets/reference_photos/`; список и назначения — `reference_manifest.json`.
- Классификация ракурса и идентификация одного и того же грузовика пока не подключены. Анализ качества реализован как локальная эвристика и требует калибровки.
- Автоматическая идентификация одного и того же грузовика по фото не гарантируется и потребует отдельной модели/проверки.
- Telegram и сервер отсутствуют по текущему решению.
- Это исходный Android Studio проект, а не собранный APK. Сборка выполняется в Android Studio с установленным Android SDK.

## Эталонные фотографии
Все 23 фотографии, переданные в переписке, включены в assets. Несколько фотографий одного типа объединены под одним заданием; перечень можно менять в `MainActivity.kt` и `reference_manifest.json`.


## Примечание к обновлению 0.2.0
Схема локальной базы Room обновлена. На этой ранней стадии используется `fallbackToDestructiveMigration()`: при обновлении базы с версии 0.1.0 старые тестовые записи могут быть удалены. Перед использованием на реальных осмотрах это поведение нужно заменить полноценной миграцией.


## Сопоставление ракурса с эталонами (версия 0.3.0)
- После съёмки приложение сравнивает изображение с 23 эталонными фото из assets.
- Для сравнения строится компактный дескриптор распределения границ/контуров по сетке изображения.
- Система ищет наиболее похожую группу ракурсов и сравнивает её с выбранным заданием.
- Если предполагается другой ракурс или уверенность недостаточна, приложение показывает предупреждение.
- Сотрудник может переснять фото или подтвердить его вручную.
- Для завершения осмотра обязательный кадр должен пройти проверку качества и проверку ракурса либо быть подтверждён вручную.

**Ограничение:** это экспериментальное сопоставление визуальных признаков, а не обученная нейросеть и не гарантированное распознавание ракурса. Оно может ошибаться при другом автомобиле, фоне, расстоянии и освещении. Пороговые значения и алгоритм нужно проверить на реальных снимках разных грузовиков. Следующий шаг для надёжного распознавания — собрать размеченный набор фото по ракурсам и обучить/подключить компактную модель классификации.


## Сбор обучающих фотографий (версия 0.4.0)
- При успешной автоматической проверке фото копируется в локальную папку `training_samples/<task_id>/`.
- При ручном подтверждении снимок также попадает в набор-кандидат с меткой выбранного задания.
- На главном экране есть «Экспорт обучающих фото»: создаётся ZIP с изображениями и `manifest.csv`, затем Android открывает системное меню «Поделиться».
- Метка означает выбранный ракурс задания, поэтому перед обучением экспорт нужно проверить вручную. Неверно размеченные фото нельзя использовать для обучения.

### Подготовка первой модели
В папке `training_tools/` находится стартовый скрипт обучения MobileNetV2 → TensorFlow Lite:
1. Распакуйте экспортированный ZIP в `training_tools/dataset/`.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Запустите `python train_classifier.py`.
4. Полученные `output/angle_classifier.tflite` и `output/labels.json` — кандидаты для следующего этапа интеграции в Android.

Для осмысленного обучения ориентир — хотя бы 50–100 разнообразных фото на каждый ракурс, желательно с нескольких разных грузовиков, разных фонов, расстояний и освещения. Для проверки качества модели нужны отдельные тестовые фотографии, которые не участвовали в обучении. Текущий Android-классификатор по дескрипторам остаётся резервным экспериментальным механизмом; TFLite-модель в приложение пока не встроена.


## Подключение TensorFlow Lite (версия 0.5.0)
- Добавлена зависимость TensorFlow Lite Runtime.
- Добавлен загрузчик `TfliteAngleModel`: приложение проверяет наличие `angle_classifier.tflite` и `labels.json` в `app/src/main/assets/`.
- Если файлы модели присутствуют, используется TFLite-предсказание; если отсутствуют, используется прежнее экспериментальное сравнение с эталонами.
- В ZIP намеренно не включена фиктивная/необученная модель. Реальное распознавание нейросетью активируется только после обучения на размеченном наборе и копирования обоих файлов в assets.

### Важно для первого запуска обученной модели
Скрипт обучения формирует модель MobileNetV2 с входом 224×224 RGB и нормализацией [-1; 1]. Android-загрузчик ожидает тот же формат входа и выходной вектор вероятностей с порядком классов из `labels.json`. После добавления модели обязательно проверьте совпадение labels с `taskId` в `MainActivity.kt` и протестируйте на новых грузовиках.
